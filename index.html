¿Qué hace?

Esta clase es el "encargado" del catálogo: sabe leer, guardar, buscar, agregar, cambiar y borrar perfumes. Las demás páginas le piden las cosas a él en lugar de hacerlas por su cuenta. Vamos por partes:

Al inicio del archivo

  • using ...;: son los "permisos" para usar herramientas que ya trae .NET. Por ejemplo, System.IO sirve para trabajar con archivos y System.Text.Json para leer y escribir JSON.
  • using PerfumeriaPIA1.Models;: nos deja usar la clase Perfume que creamos antes.
  • namespace PerfumeriaPIA1.Services: el "cajón" donde vive esta clase, igual que en Models.

Los datos de la clase

  • _rutaArchivo: guarda la ubicación del archivo perfumes.json, donde se guardan los perfumes. readonly significa que, una vez asignado, ya no se puede cambiar.
  • _perfumes: la lista de perfumes mientras la app está abierta. List<Perfume> se lee "lista de perfumes".

El constructor: PerfumeService()

Se ejecuta automáticamente cuando alguien crea un PerfumeService. Hace dos cosas:

  • Path.Combine(AppContext.BaseDirectory, "perfumes.json"): arma la ruta del archivo, en la misma carpeta donde se ejecuta la app.
  • CargarDatos(): llena la lista con los perfumes guardados.

CargarDatos

  • File.Exists(...): pregunta si el archivo ya existe.
  • Si existe, File.ReadAllText lo lee y JsonSerializer.Deserialize convierte ese texto en una lista de perfumes. El ?? new List<Perfume>() significa "si algo sale vacío, usa una lista nueva".
  • Si no existe (la primera vez que se abre la app), devuelve tres perfumes de ejemplo para que no se vea vacío.

GuardarDatos

  • JsonSerializer.Serialize: hace lo contrario, convierte la lista en texto JSON. WriteIndented = true lo deja ordenado y fácil de leer.
  • File.WriteAllText: escribe ese texto en perfumes.json. Así los cambios no se pierden al cerrar la app.

Los métodos para consultar

  • ObtenerTodos(): devuelve la lista completa. La flecha => es una forma corta de escribir "devuelve esto".
  • BuscarPorId(int id): busca un perfume por su número. FirstOrDefault trae el primero que coincida, o nada si no existe. El ? en Perfume? indica que el resultado puede venir vacío.
  • Buscar(string texto): busca por nombre o marca. Primero limpia el texto (Trim quita espacios y ToLower lo pasa a minúsculas) para que "dior" y "DIOR" den el mismo resultado. Si no escribiste nada, devuelve todos. Contains revisa si el nombre o la marca incluyen ese texto, y || significa "o".

Los métodos que modifican

  • Agregar: le asigna un Id nuevo (el más grande que exista más uno, o 1 si no hay ninguno), lo mete a la lista y guarda el archivo.
  • Actualizar: busca el perfume por Id. Si no existe, devuelve false ("no se pudo"). Si existe, le copia los datos nuevos, guarda y devuelve true ("listo").
  • Eliminar: busca el perfume, lo quita de la lista, guarda y devuelve true. Si no lo encuentra, devuelve false.

ExportarCsv

  • Crea un archivo .csv, que se puede abrir con Excel.
  • StringBuilder: es como una libreta donde vamos agregando líneas de texto una por una.
  • La primera línea son los títulos de las columnas. Después, el foreach recorre cada perfume y agrega una línea con sus datos separados por comas.
  • File.WriteAllText(...): guarda todo en la ruta que se elija. Encoding.UTF8 hace que los acentos se vean bien.

¿Qué hace?

Esta clase es el "encargado" de las cuentas: sabe guardar usuarios, revisar si el usuario y la contraseña son correctos, crear cuentas nuevas y cambiar contraseñas. Funciona casi igual que PerfumeService, pero con usuarios en lugar de perfumes. Vamos por partes:

Al inicio del archivo

  • using ...;: los mismos "permisos" de antes para usar archivos, listas y JSON. Aquí no aparece System.Text porque no exportamos nada a CSV.
  • using PerfumeriaPIA1.Models;: nos deja usar la clase Usuario.
  • namespace PerfumeriaPIA1.Services: el "cajón" donde vive esta clase, junto a PerfumeService.

Los datos de la clase

  • _rutaArchivo: la ubicación del archivo usuarios.json, donde se guardan las cuentas.
  • _usuarios: la lista de usuarios mientras la app está abierta. List<Usuario> se lee "lista de usuarios".

El constructor: UserService()

Se ejecuta automáticamente cuando alguien crea un UserService. Arma la ruta de usuarios.json (en la misma carpeta donde corre la app) y llena la lista llamando a CargarDatos().

CargarDatos y GuardarDatos

  • CargarDatos: si usuarios.json ya existe, lo lee y lo convierte en una lista de usuarios. Si no existe (la primera vez), crea un usuario de prueba: admin con contraseña admin123. Con ese usuario puedes entrar la primera vez.
  • GuardarDatos: convierte la lista en texto JSON y lo escribe en usuarios.json, para que las cuentas no se pierdan al cerrar la app.

BuscarPorNombre

  • Busca en la lista al usuario con ese nombre. FirstOrDefault trae el primero que coincida, o nada si no existe, por eso el tipo es Usuario?.
  • StringComparison.OrdinalIgnoreCase: hace que no importen mayúsculas ni minúsculas. "Admin" y "admin" cuentan como el mismo usuario.

ValidarLogin

  • Es el método que usa la pantalla de inicio de sesión. Primero busca al usuario por su nombre.
  • Devuelve true solo si el usuario existe y la contraseña coincide. El && significa "y": se tienen que cumplir las dos cosas.
  • Si algo falla, devuelve false y la página muestra "Usuario o contraseña incorrectos".

Registrar

  • Es el método que usa la pantalla de crear cuenta.
  • Si ya existe alguien con ese nombre, devuelve false y no crea nada, para que no haya dos usuarios iguales.
  • Si el nombre está libre, agrega el usuario nuevo a la lista, guarda el archivo y devuelve true.

CambiarContrasena

  • Es el método que usa la pantalla de recuperar contraseña.
  • Busca al usuario. Si no existe, devuelve false.
  • Si existe, le pone la contraseña nueva, guarda el archivo y devuelve true.

📄 Tercer paso: Las 7 páginas

Ahora vamos a crear las pantallas de la app. Son siete: LoginPage, RegisterPage, ForgotPasswordPage, DashboardPage, PerfumesPage, ProfilePage y SettingsPage.

Cómo crear cada página

  1. Haz clic derecho en el proyecto PerfumeriaPIA1, selecciona Agregar y luego Elemento nuevo...
  2. Elige Página en blanco (WinUI 3). Cuidado: no elijas "Ventana en blanco", porque necesitamos una Page (página).
  3. Escribe el nombre antes de dar clic en Agregar (por ejemplo, LoginPage).
  4. Cada página crea dos archivos: uno .xaml (cómo se ve) y uno .xaml.cs (qué hace).

Regla para no confundirte

  • El código que empieza con <Page o <Window va en el archivo .xaml.
  • El código que empieza con using va en el archivo .xaml.cs.
  • Siempre haz lo mismo: Ctrl+A (seleccionar todo), borrar, y pegar el código nuevo.

Aviso importante

Mientras no termines todos los pasos, la Lista de errores va a mostrar errores. Es normal: algunas páginas usan cosas que todavía no existen, como MainWindow, que ya viene creada con el proyecto y la vamos a modificar en el Paso 4. Al final deben quedar en 0.

¿Qué hace?

Este archivo solo describe cómo se ve la pantalla. Se construye con "cajas" dentro de otras cajas:

  • <Page ...>: es la página completa. x:Class="PerfumeriaPIA1.LoginPage" la conecta con su archivo .xaml.cs. RequestedTheme="Light" fuerza el tema claro.
  • <Grid> con dos ColumnDefinition: divide la pantalla en dos columnas. La izquierda es decorativa y la derecha tiene el formulario. 1* y 1.2* son proporciones: la derecha es un poco más ancha.
  • LinearGradientBrush: el degradado de verde claro a verde un poco más fuerte del fondo izquierdo.
  • Canvas y Rectangle: con rectángulos redondeados se dibuja el frasco de perfume. Canvas.Left y Canvas.Top dicen en qué posición va cada pieza.
  • StackPanel: apila lo que lleva dentro, uno debajo del otro. Spacing es la separación entre ellos.
  • Border con CornerRadius: la cajita de fondo con esquinas redondeadas que rodea cada campo.
  • TextBox: donde se escribe el usuario. PasswordBox: donde se escribe la contraseña (muestra puntitos). PlaceholderText es el texto gris de ayuda.
  • x:Name="...": es el nombre que le damos a un elemento para poder usarlo desde el código de C#. Por ejemplo, TxtUsuario.
  • Click="BtnLogin_Click" y KeyDown="Campo_KeyDown": conectan el botón (o una tecla) con un método del archivo .xaml.cs. Ese método se ejecuta al dar clic o al presionar una tecla.
  • CheckBox: la casilla "Recordarme". HyperlinkButton: un botón con aspecto de enlace, para "Olvidé mi contraseña" y "Crear cuenta".
  • TxtError: un texto rojo y vacío donde después aparecerá el mensaje si el login falla.

¿Qué hace?

Este archivo es el cerebro de la pantalla: decide qué pasa cuando el usuario hace algo.

Al inicio del archivo

  • using ...;: los "permisos" para usar herramientas de WinUI (botones, teclas, navegación) y de Windows (Windows.Storage guarda configuraciones pequeñas).
  • using PerfumeriaPIA1.Services;: nos deja usar UserService.
  • public sealed partial class LoginPage : Page: la clase de esta pantalla. : Page significa que "es una página".

Los datos de la clase

  • ClaveUsuario: una etiqueta fija (const = constante) para guardar y buscar el usuario recordado.
  • _userService: el "encargado" de las cuentas que creamos antes. Lo usamos para validar el login.

El constructor: LoginPage()

  • InitializeComponent(): construye en pantalla lo que escribimos en el .xaml. Siempre va primero.
  • new UserService(): crea el encargado de las cuentas.
  • CargarUsuarioRecordado(): revisa si antes se marcó "Recordarme".

CargarUsuarioRecordado

  • ApplicationData.Current.LocalSettings.Values: un "cajoncito" donde Windows guarda datos pequeños de tu app, aunque la cierres.
  • Si ahí hay un usuario guardado, lo escribe en el campo de usuario y marca la casilla "Recordarme". El && significa "y": se tienen que cumplir todas las condiciones.

GuardarOLimpiarUsuario

  • Si la casilla "Recordarme" está marcada, guarda el nombre de usuario en el cajoncito.
  • Si no está marcada, lo borra con Remove.

Campo_KeyDown

  • Se ejecuta cada vez que se presiona una tecla en el campo de usuario o de contraseña.
  • Si la tecla es Enter, hace lo mismo que el botón LOGIN. e.Handled = true evita que la tecla haga otra cosa (como un sonido).

BtnLogin_Click

  • Toma lo que escribió el usuario (Trim() quita los espacios de sobra) y le pregunta a ValidarLogin si es correcto.
  • Si es correcto: guarda o limpia el usuario recordado, le dice a la ventana principal quién entró, muestra el menú verde y navega al Dashboard. MainWindow.Instancia es la ventana principal de la app, que modificamos en el Paso 4. El ?. significa "hazlo solo si existe".
  • Si no es correcto: muestra en rojo "Usuario o contraseña incorrectos."

Frame.Navigate(typeof(...)) cambia a otra página. Uno lleva a RegisterPage (crear cuenta) y el otro a ForgotPasswordPage (recuperar contraseña).
